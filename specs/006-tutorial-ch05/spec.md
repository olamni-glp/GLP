- Q10 (2026-05-01 spec amendment, post-empirical-review of §5.6): book p 51 §5.6 typed quicksort has TWO book-internal issues that prevent byte-exact transcription from loading. Both confirmed empirically (test4a/b/c/d on REPL build `bcd59392`, 2026-05-01).

  **Issue A — qsort declaration typo.** PDF prints:
  ```
  procedure qsort(NumList?, NumList?, NumList).
  ```
  This is consume/consume/produce. But the book's prose immediately below states "qsort: consumes list, produces accumulator head, consumes accumulator tail" (consume/produce/consume), AND the body of `quicksort/2` calls `qsort(Unsorted?, Sorted, [])` where `Sorted` is a writer (matches produce mode at arg 2), AND the qsort clauses themselves use `qsort([X|Unsorted], Sorted?, Rest)` where `Sorted?` is reader at arg 2 (head expects reader at produce mode). All three lines of evidence (prose, body call, clause heads) agree the declaration should be:
  ```
  procedure qsort(NumList?, NumList, NumList?).
  ```
  Empirical: test4d (interleaved layout + printed typo'd declaration) fails with mode-mismatch errors at clause heads and body atoms (`Variable mode mismatch: writer requires ↑ (produce), got ↓ (consume) Path: (Rest, 0, input)` etc.). test4c (interleaved + corrected declaration) loads `✓ Loaded:` cleanly. **→ Amended**: ex-05's `.glp` declares `procedure qsort(NumList?, NumList, NumList?).` (corrected per prose + clauses). The `%%` paraphrase comment on the qsort declaration explicitly documents the Q10 amendment with provenance ("printed PDF text shows `(NumList?, NumList?, NumList)` which contradicts the prose + clause shapes; prose-consistent form used per Q10 amendment").

  **Issue B — stacked-declarations layout.** PDF prints all three procedure declarations stacked at the top of §5.6, then all six clauses below. The REPL parser requires each `procedure` declaration to be **immediately followed by its clauses** — the same constraint that motivated Q7's §5.3 + §5.4 merger. Empirical: test4a (stacked, printed signature) and test4b (stacked, corrected signature) both fail with `[syntax] Procedure declaration for "quicksort" has no clauses. A procedure declaration must be immediately followed by its clauses. at Line 4, Column 1`. **→ Amended**: ex-05's `.glp` interleaves the three declarations with their respective clauses:
  ```
  NumList ::= [] ; [Number | NumList].

  procedure quicksort(NumList?, NumList).
  quicksort(Unsorted, Sorted?) :- qsort(Unsorted?, Sorted, []).

  procedure qsort(NumList?, NumList, NumList?).      %% Q10 corrected per prose + clauses
  qsort([X|Unsorted], Sorted?, Rest) :- … .
  qsort([], Rest?, Rest).

  procedure partition(NumList?, Number?, NumList, NumList).
  partition([X|Xs], A, Smaller?, [X?|Larger?]) :- … .
  partition([X|Xs], A, [X?|Smaller?], Larger?) :- … .
  partition([], A, [], []) :- number(A?) | true.
  ```
  The clause text remains byte-exact from the PDF; only the **layout** is amended (the parser-required interleaving). The `.glp` file's header block explicitly documents the Q10 layout amendment with Reason: "PDF stacks the three procedure declarations at the top and clauses below; the REPL parser requires immediate-clause-after-decl, so declarations and clauses are interleaved per Q10 amendment."

  This is a genuine book-vs-implementation gap, not a fabrication. The pedagogical content (typed sort algorithm, mode declarations, recursion) is preserved exactly.

### Edge Cases

- **Dart SDK absent on the host machine.** Implementation halts at REPL build; tutorial author reports back to the project owner before proceeding. The learner-facing tutorial documents that a working GLP REPL is a prerequisite.
- **REPL build fails (e.g., dependency / version mismatch).** Implementation halts; failing-build trace is reported to the project owner. The learner-facing tutorial does NOT contain a synthesised "expected" trace if a real one cannot be captured.
- **Type-checker is in a broken state at REPL load.** ch05 spec REQUIRES a working type-checker. If the type-checker rejects code that the PDF presents as valid (false positive on positive exercises), or accepts code that the §5.7 negative examples require be rejected (false negative on negative exercises), the implementer halts per FR-013 and reports. ch05 work does not proceed against a broken type-checker.
- **PDF transcription mismatch between `ch05-sources.md` and `GLP_ART.pdf`.** PDF is canonical; if the sources index has a typo, it is corrected during implementation by re-reading the PDF byte-exactly. For ch05 specifically, ~10 substantial code blocks need byte-exact verification with extra attention to `?` reader marks, `;` alternation separators, and `|` list-cons separators (the syntactic elements the chapter introduces).
- **Negative-exercise error message format depends on REPL build version.** The type-checker's error messages may evolve. The implementer captures error messages exactly as the current build emits them, locks them at /speckit-implement T026/T037-equivalent, and notes in the trace's annotation that the message format depends on the REPL build version. If a future REPL build changes the message, the trace becomes inconsistent — workflow memory tracks this as a known maintenance item.
- **Negative-exercise error contains per-run-varying segment** (memory address, tuple-id, etc.). The implementer halts at /speckit-implement T026/T037-equivalent and proposes a per-run-variation relaxation analogous to ch02's FR-014 amendment (`varies per run; the SHAPE matters, not the specific number`). Otherwise full byte-equality holds for negative-exercise error messages.
- **Spec-locked decision found incompatible with SRSW or type-check at REPL load** (ch02 Q3a precedent + ch03 Q4 precedent + ch04 Q4–Q10 precedents). Halt and propose a Clarifications amendment preserving audit trail; never silently substitute a locked shape with a different one. - **Type-definition-only exercise's helper unit-clause violates SRSW or type-check.** The minimal helper proposed at /speckit-plan T006-equivalent for ex-01, ex-02, ex-03 (Option A) is part of the spec-locked decision; if the proposed helper turns out to violate SRSW or type-check at REPL load, halt and propose an amendment to the helper shape (NOT to the byte-exact PDF type definition, which is locked).

# Feature Specification: Olamni Tutorial — Chapter 7 (Module System)

**Feature Branch**: `008-tutorial-ch07`
**Created**: 2026-05-01
**Status**: Draft
**Input**: User description: "Build a tutorial for chapter 7 of the GLP book — 'Module System.' Adhere to the style and format of the REPL exercises already established for ch01..ch06. ch07 is fundamentally different from chs 1–6 because it is the first chapter whose runnable example is a complete *set* of modules (multiple `.glp` files) loaded from a root module via the project-loader. The complete loading — root module + all dependencies via implicit ancestor scoping + cross-module imported procedures — must be accessible to the learner in BOTH the traditional REPL-based exercise format AND the new Flutter+play+boot environment used from chs 7 onward. Tests that mirror the chapter content must be defined. The chapter has TWO multimodule clusters: (A) the simpler §7.3 social/agent example at the start of the chapter, and (B) the §7.7 CSSG (Child-Safe Social Graph) validation example in the second part. Total exercises ≤ 15, with each cluster getting ≥ 5 and ≤ 8. REPL exercises must contain copy-pastable load lines and goal prompts that the learner can lift verbatim into a REPL session. ONE Flutter exercise must walk the learner through the full Flutter+play+boot setup — manually verified, copy-pastable terminal commands, including a recommended clean session if needed before launching Flutter with play+boot for either cluster's example."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Cluster A: Simple multimodule project — REPL exercises (Priority: P1)

A learner who has finished chs 1–6 reads §7.1–§7.6 and opens `olamni/tutorial/ch07/exercise-01/` through `exercise-05/`. These five REPL exercises operate on the **simple multimodule project** at `olamni/tutorial/ch07/simple-multimodule/{self.glp, agent.glp, boot.glp}` (a stripped-down social/agent layout per book §7.2 + §7.3, derived from `programs/cssg_modules/` reduced to a single 3-agent cold-call play). The learner loads the project via the REPL's project-loading mode; observes ancestor-scoped types from `self.glp` resolving without imports; reads exported / private / imported declarations; sees procedure renaming and entry-point aliases after project compilation; and runs the play to completion. Each exercise is a focused walkthrough of one §7.x mechanic (project tree → declarations → ancestor scoping → procedure renaming → end-to-end run).

**Why this priority**: P1 because cluster A establishes every module-system mechanic (§7.1–§7.6) that cluster B then applies at scale. Without cluster A's REPL drills, cluster B's CSSG project would feel like a 2,500-line wall.

**Independent Test**: For each cluster A REPL exercise (ex-01..ex-05), open the exercise dir, follow `ex-NN-tutorial.md` line-by-line in a fresh REPL session — copy-pasting every load line and goal prompt verbatim — and reproduce the captured `ex-NN-repl-trace.md` modulo banner / build wallclock lines.

**Acceptance Scenarios**:

1. **Given** the learner has built the REPL per the chapter signpost, **When** they copy-paste ex-01's load command into a fresh REPL session, **Then** the simple-multimodule project loads end-to-end (discovery → type checking → procedure renaming → call resolution → entry-point alias generation per §7.5) and the REPL prints `✓ Loaded:` for each module + a completion line for the project.
2. **Given** ex-02 is loaded, **When** the learner runs the inspection goals from `ex-02-tutorial.md` that probe the three procedure-decl kinds (private / exported / imported), **Then** the REPL output demonstrates that callers outside `agent.glp` can reach `agent#agent/4` (exported) but cannot reach `agent#merge/3` (private) and that boot's `agent # agent(...)` call site resolves through the local `imported procedure` declaration without the type-checker reading `agent.glp` source (per Formal 7.2 and §7.4).
3. **Given** ex-03 is loaded, **When** the learner runs the ancestor-scoping inspection goals, **Then** the trace shows that types defined in `simple-multimodule/self.glp` (e.g., `Response`, `AgentContent` per §7.3 prose) are visible from `agent.glp` and `boot.glp` without any import directive (per Formal 7.1 type-scope assembly).
4. **Given** ex-04 is loaded, **When** the learner runs the procedure-renaming inspection goals, **Then** the trace shows the renamed-procedure namespace per §7.5's renaming table (e.g., `agent.glp:merge/3 → agent:merge/3`, `boot.glp:play1/0 → boot:play1/0`) and the entry-point alias `play1 :- boot:play1.` resolves a top-level `play1.` call.
5. **Given** ex-05 is loaded, **When** the learner runs `play1.` (the cluster A play), **Then** the play completes (`→ succeeds` or `→ suspended` for plays whose channels remain open, per charter §2.2) and the trace's annotation explicitly cross-references which §7.x mechanics were exercised end-to-end.

The learner-facing tutorial documents that a working GLP REPL is a prerequisite (cluster A) AND a working Flutter SDK is a prerequisite (cluster A's ex-06 + cluster B's ex-12).
- **Flutter SDK absent or version-incompatible.** ex-06's pre-flight section halts the learner with explicit version-check commands; the tutorial does NOT silently substitute a different Flutter version.
- **Platform-specific Flutter behaviour.** The captured trace records the platform under which it was generated; the tutorial documents that paths and log file locations may differ across macOS / Linux / Windows and points the learner to the per-platform variants.
- **Stale Flutter build cache.** ex-06's "recommended clean session" block (`pkill` + `flutter clean` + `flutter pub get` + `flutter build`) is presented when the captured trace was generated after a clean session; the tutorial documents this so the learner knows when to use it.
- **Cluster B's tutorial copy of `cssg-modules/` drifts from `programs/cssg_modules/`.** The byte-equivalence test (per FR-014) catches the drift; halt and report. If `programs/cssg_modules/` is the canonical copy and the tutorial copy is downstream, the implementer re-syncs from canonical and re-runs the tests.
- **§7.7 references "Chapter ??" for parameterized types.** Book p 61's last paragraph states that `boot.glp`'s untyped status motivates "the extension presented in Chapter ??" (the book's reference to a later chapter that isn't yet finalized). The tutorial signposts this gap as plain prose and does NOT speculate which later chapter resolves it.
- **CSSG play that suspends rather than completes.** Several CSSG plays leave channels open by design (per the bonds-plays precedent in CLAUDE.md §12); `→ suspended` is a valid outcome and is annotated as such in the trace.
- **Flutter app launches but the platform log file is missing or empty.** The tutorial's troubleshooting section documents the per-platform log path discovery procedure and the expected log-line shapes; if the log is empty, the implementer halts and reports per FR-013.
- **Multi-Claude collaboration on the same branch.** Per CLAUDE.md §14, only commit files this session modified; do NOT `git add -A`. ch07's branch is `008-tutorial-ch07` and is owned by the implementing session; merges to main are user-initiated.
- **Spec-locked decision found incompatible with the project loader at REPL load** (ch02 Q3a / ch03 Q4 / ch04 Q5–Q10 / ch06 Q-amendments precedent). Halt and propose a Clarifications amendment preserving audit trail; never silently substitute a locked shape with a different one.

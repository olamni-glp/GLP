### User Story 1 - Programs with Constants — load and run §4.1 exercises (Priority: P1)

A learner who has read book §4.1 (Programming with Constants, pp 25–30) opens the chapter-4 ex-01 and ex-02 directories. ex-01 contains the §4.1 unit-clause Programs (`p(a)`, `q(b)`/`q(a)` multi-clause, logic gates `and/3` + `or/3` + `not/2` + `xor/3`); ex-02 contains the §4.1 compound-circuit Programs (`nand/3` first-clause-with-body, `half_adder/4` with `ground` guards on multiple readers, `full_adder/5` composing the prior gates). The learner loads each exercise's `.glp` file, runs the primary demo goal plus three inspection goals, and observes how unit-clauses + multi-clause committed-choice + body-using clauses + multi-reader-ground-guards build up to compound circuits per Formal 4.1.

**Why this priority**: P1 because §4.1 is the chapter's foundational content and every later sub-section assumes it. Without ex-01 + ex-02 the learner cannot proceed to §4.2 streams (which builds on the same SRSW reader/writer discipline applied across stream operators).

**Independent Test**: Open `olamni/tutorial/ch04/exercise-01/ch-04-ex-01-<short-name>.glp` in the GLP REPL, load it, run the primary demo goal selected during /speckit-plan; observe the locked binding. Then open exercise-02; load it; run its primary; observe the binding. Both files load with zero errors (no SRSW violation, no type error, no compile error).

**Acceptance Scenarios**:

1. **Given** the learner has read §4.1, **When** they load ex-01's `.glp`, **Then** the REPL prints `✓ Loaded:` and `p/1`, `q/1`, `and/3`, `or/3`, `not/2`, `xor/3` are all defined in the procedure table.
2. **Given** ex-01 is loaded, **When** the learner runs the primary demo goal selected during /speckit-plan, **Then** the goal succeeds with the locked binding documented in `research.md`. Empirically verified during /speckit-implement; mismatch is halt-and-report per FR-013.
3. **Given** ex-02 is loaded, **When** the learner runs the half_adder / full_adder primary goal, **Then** the binding matches the locked binding AND the trace's annotation explicitly notes that the `ground` guards on multi-reader head positions are what Formal 4.1 (book p 29) describes.

### User Story 4 - Metaprogramming — load and run §4.4 exercises (Priority: P2)

After mastering §4.3, the learner opens ex-09 (programs-as-data + trust-mode meta-interpreter) and ex-10 (advanced meta-interpreters: fail-safe, control with control-stream, tracing with deterministic replay). Across two exercises the learner sees the §4.4 metaprogramming foundations — encoding GLP programs as data, then writing meta-interpreters that step through them with trust mode, with failure tolerance, with controllability (suspend/resume/abort), and with deterministic replay.

**Why this priority**: P2 because §4.4 is conceptually advanced (a meta-level on top of all prior content) but completes the chapter. Without §4.4, ch04's "implemented" state would exclude one of the book's four sub-sections. Per project-owner directive (Q1=A), §4.4 is fully in scope.

**Independent Test**: Load ex-09; run `run(merge, merge([1,2],[3,4],Z)).` (trust-mode MI) — observe `Z = [1,3,2,4]` (or whichever locked binding matches the chosen merge-program-as-data encoding). Load ex-10; run the fail-safe / control / tracing variants per the locked goal set.

**Acceptance Scenarios**:

1. **Given** ex-09 is loaded, **When** the learner runs the trust-mode MI primary goal, **Then** the locked binding matches AND the trace shows the MI stepping through the program-as-data encoding.
2. **Given** ex-10 is loaded, **When** the learner exercises the control-stream MI with a suspend/resume/abort goal sequence, **Then** the trace shows the corresponding state transitions.
3. **Given** the tracing MI's deterministic-replay capability, **When** the learner runs a goal under tracing then replays the same trace, **Then** the replay produces byte-identical output (the basis of the deterministic-replay claim).

### Edge Cases

- **Dart SDK absent on the host machine.** Implementation halts at REPL build; tutorial author reports back to the project owner before proceeding. The learner-facing tutorial documents that a working GLP REPL is a prerequisite.
- **REPL build fails (e.g., dependency / version mismatch).** Implementation halts; failing-build trace is reported to the project owner. The learner-facing tutorial does NOT contain a synthesised "expected" trace if a real one cannot be captured. Note: omitting `--define=GLP_BUILD_COMMIT=...` is NOT a build failure when the build-provenance fix branch (`claude/fix-misleading-build-line`) is unmerged; the build proceeds with `Built from: unknown` banner.
- **PDF transcription mismatch between `ch04-sources.md` and `GLP_ART.pdf`.** PDF is canonical; if the sources index has a typo, it is corrected during implementation by re-reading the PDF byte-exactly (per ch01's predict-and-verify lesson). For ch04 specifically, ~38 substantial code blocks need byte-exact verification — implementer plans time accordingly.
- **Spec-locked decision found incompatible with SRSW at REPL load** (ch02 Q3a precedent + ch03 Q4 precedent). Halt and propose a Clarifications amendment preserving audit trail; never silently substitute a locked shape with a different one.
- **§4.4 meta-interpreter goal that suspends rather than succeeds** (e.g., a control-stream MI waiting for a control directive). The trace covers `→ suspended` as a valid outcome where applicable. Distinct from ch03 Edge Case M1's deterministic-fails contract for ground-input no-match cases.
- **Cross-chapter inversion mismatch — ch03 ex-01's imported `producer/2` + `consumer/3` byte-exact form drifts from ch04 ex-03's native form.** Halt and report; the byte-exact code MUST be identical between ch03's import and ch04's native presentation per FR-002. Differences are only in the surrounding `%%` paraphrase comments + header block.
- **Goal sequence in a §4.4 meta-interpreter goal exceeds REPL execution limit (`:limit`).** Implementer either bumps the limit via REPL `:limit` command before running the goal, OR chooses a smaller-input goal that completes within the default limit. Documented in trace if the limit is bumped.
- **Within-group exercise order shift requested mid-implementation** (e.g., implementer realises ex-04 should depend on ex-05 internally). Halt-and-amend per FR-013; group-boundary gates are spec-locked, not the within-group order.

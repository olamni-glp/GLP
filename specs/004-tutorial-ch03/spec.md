The locked primary goal `lookup(b, [(a,1),(b,2),(c,3)], V).` and locked binding `V = 2` are preserved unchanged. Pedagogical content (positive `=?=` in clause 1 + negated `~(=?=)` in clause 2 on the same operator + recursion descending only when negated branch fires) is preserved unchanged. Implementation re-verified empirically post-amendment; binding matches. Reason: (a) Formal 4.2 from the same author is the authoritative book-internal-consistency reference for continuation-call discipline; (b) the GLP runtime's strict SRSW enforcement is correct per Constitution Principle III and the spec; (c) the alternative — accepting the byte-exact form and treating the runtime as buggy — would conflict with both Formal 4.2 and the strict-SRSW Constitution principle; (d) ch02 Q3a precedent established that runtime-load-failures on locked spec shapes are amended via Clarifications entries, not silently substituted, with the audit trail preserved.

### Edge Cases

- **Dart SDK absent on the host machine.** Implementation halts at REPL build; tutorial author reports back to the project owner before proceeding. The learner-facing tutorial documents that a working GLP REPL is a prerequisite.
- **REPL build fails (e.g., dependency / version mismatch).** Implementation halts; failing-build trace is reported to the project owner. The learner-facing tutorial does NOT contain a synthesised "expected" trace if a real one cannot be captured. **Note**: omitting `--define=GLP_BUILD_COMMIT=...` is NOT a build failure — when `claude/fix-misleading-build-line` is unmerged, the build proceeds without the flag and the banner displays `Built from: unknown` (a clear signal but not blocking). Per FR-011, the implementer records the omission in `research.md` rather than halting.
- **PDF transcription mismatch between `ch03-sources.md` and `GLP_ART.pdf` p 15** (Program 3.1) **or between `ch04-sources.md` and the chosen ch4 exemplar's PDF source.** PDF is canonical; if the sources index has a typo, it is corrected during implementation by re-reading the PDF byte-exactly (per ch01 / ch02's predict-and-verify lesson).
- **Procedure-redeclaration conflict between Program 3.1's `merge/3` and the ch4 exemplar.** If the chosen ch4 exemplar redefines `merge/3` (e.g., the §4.2.5 simple fair `merge/3` candidate), the implementing session MUST halt and either (a) propose an alternative ch4 exemplar that does not redefine `merge/3`, or (b) propose a spec amendment renaming one of them in the cross-chapter import (with project-owner approval). Silent renaming is forbidden.
- **Composed primary goal binds variables to something other than the locked binding documented in `research.md`.** Halt-and-report bug; either the prediction or the runtime is wrong. Do NOT silently overwrite the spec.
- **Q2-locked `channel/1` + `process/2` shape turns out to be SRSW-incompatible at REPL load** (analogous to the ch02 `append_and_sum/4` → `/3` amendment per ch02's Q3a). Most likely culprit: the book-undefined `handle/1` body call may interact with SRSW in unexpected ways depending on which resolution (local stub vs. body substitution) /speckit-plan chose. Halt and propose a Clarifications amendment with the next-best §3.2 idiom (B alone, C alone, or D custom defined guard); record amendment in a new Clarifications entry preserving audit trail.
- **Q3-locked `lookup/3` with `~(=?=)` turns out to be parser-rejected OR runtime-incompatible** — examples seen: parser may reject the `~(...)` form on some REPL build (not seen as of 2026-04-30); runtime may emit a SRSW-related warning (`WARNING: PutVariable got unexpected value: ...`) when clause 2's body has the writer-pass-through form `lookup(Key, Rest?, V)` per byte-exact PDF (this case fired at /speckit-implement T038 on 2026-04-30 and was resolved by Clarifications Q4 amending the body to `lookup(Key?, Rest?, V)` per book Formal 4.2). For any future runtime-incompatibility, halt and either (a) propose a Clarifications amendment per the Q4 precedent (preferred when book-internal consistency justifies the change), (b) substitute another §3.2-listed negatable guard, or (c) report the parser/runtime limitation as a defect per the Bug Protocol. Per FR-013, silent shape substitution is forbidden regardless of the cause.
- **Goal that suspends rather than succeeds** (e.g., `merge(X?, Y?, Z).` with unbound writer / reader pairings the inspection goal didn't anticipate). The tutorial covers `→ suspended` as a valid outcome, not a failure, in the inspection-goal walkthrough where applicable. **Exception for ex-03 inspection 3**: `lookup(z, [(a,1),(b,2),(c,3)], V).` operates on a fully-ground input list; after recursion descends to `lookup(z, [], V)` the empty list is ground, neither `lookup/3` clause head matches, and the procedure MUST deterministically produce `→ fails`.
